Enforce the funding pause on the shared funding-settlement helper (OtterSec finding #65). On-chain program hardening (no SDK API change): the public fill, perp-position-transfer, PnL-settle, and liquidation paths call `settle_funding_payment`, which folds already-accrued cumulative funding into a position's quote balance. That helper previously ran unconditionally while the dedicated `settle_funding_payment` crank was gated by `funding_not_paused`. It now takes a `funding_paused` flag (threaded from `State::funding_paused`) and no-ops when the exchange-wide funding pause is set, so pending funding is left unapplied — the position's `last_cumulative_funding_rate` is untouched and the next settlement after funding resumes covers the full elapsed interval. The total economic value of a position (settled + unsettled funding) is unchanged, so SDK funding/margin math is unaffected; a client simulating the exact on-chain `quote_asset_amount` mutation during a pause should note that funding is no longer folded in until the pause lifts. A liquidation during a pause values a position without realizing its pending funding (intended behavior). No account-layout, IDL, or error-enum change.
