| 2026-08-21 | — (implementation) | **The CLOB stops being special.** Its layout was restated in velocity as byte-offset literals and read from four off-chain places, so a book that changed its data structures broke everyone downstream. Three changes. (1) New crate `crates/clob-spec` declares the market account's layout once — `OrderNodeV0`, the header offsets, the arena — and the book const-asserts its own structs against it, so a moved field is a compile error rather than a silent misparse. (2) New optional quoter leg `quote_l3_v0` (≤128 `L3RowV0`, sized to the response region the market already pays for) reports the orders behind a ladder and who each belongs to; `quote_router` writes them into `RouterQuoteBufferV0` (now 41,736 bytes) and attributes a leg-less quoter's ladder to its registered user, so every source answers the same shape. Deletes `velocity-rs::clob`, keep-rs's book read, swift `/route`'s second walk (it answers from the view it already ran) and the publisher's L3/best-makers/cross walks; off-chain discovery is `velocity_router_sim::l3::resting_makers`, which simulates. (3) The executor's book-derived subject set is gone: reading the arena checked the book program against its own state. A `Clob` entry may settle for any loaded user but the taker, and what bounds it is that the type is a warm-admin decision, the market's book is designated once and never swapped, and the price and margin checks still apply. View cost: 61.1k → 67.6k CU for CLOB+vAMM, and a fill leg is cheaper by the walk it no longer does. |
| 2026-08-21 | — (implementation) | **Quoter-wire heap cut.** A `quote_router` pass over five registered quoters ran out of heap and published nothing: velocity's heap is 32 KB, its allocator never reclaims, and each quoter cost ~2.3 KB — 1,772 bytes of it the CPI arg buffer, whose fixed-width user set was 1,633 bytes of zeros on a view that names no users. Two changes. (1) `QuoteArgsV0`/`ExecuteArgsV0` carry `users` as a borrowed sequence (4 bytes empty, ≤1,636 full) that a quoter reads in place, written by velocity through wincode (`quoter_spec::write_args` / `args_size`, framed by `ARGS_CONFIG` = anchor v2's `BORSH_CONFIG`) rather than borsh's `Vec` impl; quoters check `user_set_within_capacity` (new `OversizedUserSet` in both) because the caps bitmap addresses users by set index. Anchor v2 is now a velocity fork one commit past otter-sec's `4fbe613`: that macro wrote lifetime arguments into the CPI wrapper's instruction literal, which Rust cannot parse, so borrowed handler args did not compile at all. (2) The quote view reads each ladder in place (`quote_in_place` + `checked_quote_response`) and copies it once, into the buffer, clamping as it copies (`push_capped`); the vAMM's rivals are `bytemuck` casts onto the buffer. Measured with the litesvm bench (`bench_quote_router_wall_clock`): five quoters used to run out of heap, and a pass now carries eight with a 32-rung spline each (256 levels, 308k CU) — the binding constraint is back to the transaction's account list, where a midpoint quoter costs four slots. |

## Design snapshot

Terse restatement of decided design, for cross-referencing. Numbered so tasks can cite it (S1–S7).

1. **Quoter interface**: program exposing `quote_v0`/`execute_v0`; raw 8-byte discriminators; borsh args after discriminator. Responses are written into the quoter's registered response account (owned by the quoter program); return data carries only a ResponsePointerV0 (offset, len) into it (writer must be the quoter program), so payloads are not bound by the 1024-byte return-data cap. Quote/execute args carry the set of `User`s velocity has loaded (`users: Option<Vec<Pubkey>>`, `None` = unrestricted off-chain discovery); quoters must not fill anyone else, and velocity rejects returned balance changes for unloaded users. CPI data cost is ~32 B/user and the list is bounded by the tx account budget anyway (every listed user is a writable account in the tx), so size is a non-issue. Registered in a `QuoterV0` registry entry (user, program_id, response_account, discriminators, account lists, type, is_active/is_approved). **Quoter CPIs never receive signer privilege** — every forwarded account is `is_signer: false`, because signer status propagates through CPI and an untrusted quoter handed a taker wallet could drain it. Quoters verify who signed the outer transaction (e.g. the `flow_authority` attestation) via instructions-sysvar introspection. Velocity may still sign as its own PDA with `invoke_signed` (that is velocity signing as itself, not forwarding).
2. **CLOB**: standalone program. Node arena + free list + two best-first sorted intrusive linked lists; `NIL = u32::MAX`; velocity `User` pubkey inline on the node (no seat table). Velocity price/size units; tick/step/min enforced at place, not in storage. Per-side reserved capacity; eviction is crank-mediated (decided 2026-07-28, replacing inline better-price tail eviction): `evict_worst_v0` removes the side's tail once the side is at/above `evict_threshold_per_side` (soft cap), and a full side rejects every placement — even better-priced — until the crank catches up (hard cap = ops failure; the buffer + keeper reward keep it clear). `activation_slot` speed bump (default +1 slot, may be set to 0 — dropping the bump is under consideration; max 20 = auction) — this replaces JIT. `flow_authority`-signed attestation (200–400ms API hold) bypasses the delay; quoters introspect the signer, no args flag. Expiry (`max_ts`) only skipped by quote/execute, reclaimed by the `remove_expired_v0` crank (mirrors today's keeper-cranked DLOB expiry); a partial fill leaving a remainder below `min_order_size` culls the order in the same pass, reported on the wire (`ExecuteResponseV0.cancelled`) so velocity decrements aggregates — that maker was just filled, so their `User` is loaded. Cancel by verified node hint (`OrderRef`), fails closed. Fills race the tx's fixed account set: quote/execute take the loaded-user set; a matchable order whose user is absent is skipped while at most `unknown_user_grace_slots` old (keeper couldn't have known it — also kills the grief of bricking fills with fresh top-of-book orders) and fails with `StaleUserSet` once older (keeper is stale or pruning makers; queue-jumping is bounded to the grace window, so users need not be signed into the swift message). `placed_slot` on the node feeds the age check; keepers best-effort over-allocate users past quoted depth and retry on failure.
3. **Risk**: no placement-time gating for PropAMM liquidity; validation at fill. Clamp size to margin-supported max *before* the execute CPI (can't unwind external state); categorical gates (reduce-only, liquidation, equity floor, oracle validity) at the same point; returned balance changes must be at-or-better than quoted levels. Quote-time truncation is advisory. CLOB orders keep the DLOB margin model (decided 2026-07-28; `open_order_notional` + margin-floor scheme dropped): `meets_place_order_margin_requirement` at placement, resting orders counted via the existing worst-case `open_bids`/`open_asks` machinery — every path that changes exposure is velocity-mediated — place/cancel/fill directly, sub-min culls via the execute response, evict/expiry via permissionless cranks that CPI through velocity with the maker's `User` loaded — so the aggregates are exact: no drift, no reconcile ix (dropped 2026-07-28). PropAMM depth needs no declaration (`quoting_reserve` dropped 2026-07-28 — it was only load-bearing under the margin floor): routers margin-truncate quoted levels against the PropAMM user's account (the quote-time truncation above) and the fill-time clamp enforces the same bound on-chain; overquoting only degrades that maker's fill guarantee. Fill-time clamp stays for staleness, but for CLOB makers it's the edge, not the primary defense. No new crank for deteriorated accounts: the existing `force_cancel_orders` keeper ix (controller/orders.rs:3820 — fires on initial-margin/equity-floor failure pre-liquidation, skips risk-reducing orders, flat fee from the user) extends to CLOB orders via keeper-passed `OrderRef`s. Orders stranded below a raised `min_order_size` need no sweep — they were margin-gated in and just rest (tail eviction takes them if uncompetitive; execute's cull removes sub-min remainders on partial fill).
4. **Router**: off-chain `/route` picks N quoters + accounts (advisory); on-chain router computes the split from live quote CPIs. Mandatory baseline: CLOB + vAMM always in the split. Optional signed route in the swift message: every signed quoter must be present (skip if registry-deactivated); keeper is relayer for routed orders.
5. **User orders**: plain limits live only on the CLOB. `User.orders` = conditional store (needs a trigger event to become matchable). Lifecycle `Armed → Placed` (slot keeps trigger params + CLOB `OrderRef`) `→ freed | back to Armed`. Re-arm is eager — the evict crank runs through velocity with the maker's `User` loaded, so it flips the trigger slot holding that `OrderRef` back to Armed in the same tx — and edge-triggered (price must recross). Trigger-time gate mirrors today's `trigger_order` (controller/orders.rs:3738): risk-increasing + non-reduce-only + account fails initial margin / buffered equity floor / equity breaker → cancel with `InsufficientFreeCollateral`, never re-arm (checked before the place CPI instead of after going live — same outcome). UI open orders = dlob-server index over CLOB accounts; chain is truth.
6. **Priority**: admin-assigned `priority: u8` on each registry entry (decided 2026-07-28 — replaces the CLOB-first boolean); lower fills first at a shared price, pro rata within a tier. Defaults by type: vAMM 0, CLOB 10, Custom 20 (gaps for the DLOB bridge / promotions). Price beats priority — tiers apply only within a price. Consequence: a maker must beat the vAMM by a tick to see flow at that level.
7. **Migration**: DLOB wraps as a quoter for side-by-side; JIT dies at the taker-default flip (CLOB auction replaces it); phases per Notion Migration Plan.

  **The sources are not independent, so quote the set, not each source.** The vAMM's ladder shades against rival books (last look): quoted alone it prices better than it will inside a real fill, so publishing an independently-quoted vAMM book would advertise a price the taker won't get. The view instruction therefore quotes a whole batch in fill order — externals first, DLOB makers next, vAMM last with everything as its rivals — and returns per-source books. That is what the fill pass already does internally, so published books equal fill-time books by construction.

  Consequences to design around:
  - **The quoted size is part of the answer.** For CLOB/DLOB, levels are size-independent (resting orders) and a size just truncates depth; for vAMM/PropAMM the levels genuinely depend on it. So responses carry the size (and direction, and slot) they were quoted at, and a client wanting more than the UI default asks for a re-quote.
  - **Simulate on tick, not per request.** An L2 endpoint served by simulation per request would not survive fan-out. Simulate on slot/account-change, cache the book, serve reads from cache — the shape dlob-server already has for the DLOB.
  - **Batching stands.** Transaction account limits bind the quote simulation too, so a market's sources span several batches. They're local, parallel and RPC-free (the account feed keeps every touched account resident), so this is a non-issue for cost — only for the code that stitches batches together.
  - **One instruction, two consumers.** The same view instruction serves the UI book and the router's selection input, so there is exactly one definition of "what is available at what price" off-chain.
  - **The publisher has to move to Rust; the server does not (open, leaning yes).** The simulation stack is Rust-only — litesvm, `relay-chain-source`, and the program crate itself — and `apps/dlob-server` is TypeScript (`src/publishers/dlobPublisher.ts` builds books off the TS `DLOB` and writes them to Redis on a tick). Nothing bridges those: there is no TS binding for litesvm-with-cached-accounts, and reimplementing the quote view off-chain is exactly what the simulation decision rejected. So "dlob-server simulates every source" above is shorthand for a split we should make explicit: **book production moves to Rust, book serving stays in TypeScript.** The seam is already there — the publisher's output is Redis, so a Rust producer (in `rust/router-sim`, hosted by swift alongside `/route`, or a small `book-publisher` bin) writes the same keys on simulate-on-tick, and `dlobPublisher.ts` stops building books. dlob-server keeps the L2/L3 endpoints, cache reads, subscriber fan-out and auth — the parts that are genuinely a web service and would be a pure rewrite cost in Rust. What still needs deciding: the Redis payload shape (today's L2/L3 JSON unchanged, so consumers don't move, vs. a per-source shape the UI needs for the four-source book), and whether the DLOB-only path is cut over at the same time or runs alongside until the simulated books are trusted. Cost of getting this wrong is not small: if we leave it implicit, the first attempt at the uniform book lands in TS and dead-ends on the missing litesvm binding.

- **Cross-match crank (raised 2026-07-29; executor IMPLEMENTED same day — `crank_cross_match` + `controller::orders::cross_match`; remaining: the relay conditions/resolver for discovery and the publisher fast path).** Nothing matches two *resting* sources against each other today: matching only happens when a router taker fills through, so a crossed book — a CLOB bid at/above a CLOB ask, or a PropAMM bidding through the CLOB's best ask — just sits. Trigger placements make CLOB×CLOB crosses routine (an aggressive stop-limit rests crossed), and PropAMM reprices make source×source crosses routine. relay's `demo-book` models the CLOB×CLOB case as its cross condition; ours should generalize to **any two sources** (vAMM excluded: its last-look ladder prices against rivals by construction, and a transiently crossed vAMM is ordinary taker arb).

  **Mechanism (Noah confirmed the framing 2026-07-29): the protocol `User` is an arb bot through relay.** The crank is a fill in which the protocol `User` is the taker on both legs: buy X at the crossed ask, sell X into the crossed bid, both through the normal router machinery so every invariant (margin clamps on PropAMM sides, at-or-better, loaded-user rules, aggregate unwinds) is reused rather than re-implemented. Net position zero; the crossed spread lands as realized PnL in the protocol `User` — the exact sink the crank incentive loop already drains — and the keeper takes reservoir lamports in program-keeper mode. **It only crosses when the take is worth it net of fees** — no fee exemption; the executor asserts `spread − both legs' fees ≥ keeper payment`, so a resolver simulation that succeeds implies profitable, which is exactly relay's predicate model (no relay changes needed). Consequence, accepted: books can rest crossed when fees are the gulf. **Scope: CLOB×CLOB and PropAMM×CLOB only** — those strand user orders (a triggered stop-limit must fill when a PropAMM quotes through it, that's the UX this exists for); PropAMM×PropAMM crosses are external-program arb someone else picks off. Implementation (settled in the build): a dedicated two-leg pass reusing `settle_external_match_fill` with an **ephemeral taker order** on the protocol `User` (written into a free slot per leg, cleared before return, never counted anywhere) — no place-and-take round trip, no new settlement math, and no taker margin requirement since base is asserted unchanged and quote strictly grows; the fill path's pre-execute PropAMM clamp, oracle pre-flight (validity + price band), and shared post-fill maker checks all run. Litesvm-tested on an internally crossed CLOB: spread 1.0 − two 50bps taker fees = 0.9 surplus to the protocol `User`, reservoir pays the keeper, re-run with nothing crossed reverts.

  **Triggers as relay conditions (raised 2026-07-29, parked as a relay-spec v1 candidate).** Two blockers keep trigger discovery in keeper bots today: relay v0 has no threshold wake — `OnAccountChange` on an oracle fires every tick, so an armed order far from its trigger re-simulates constantly — and a resolver's fixed 4-account list can't enumerate users' armed orders (relay's stated non-goal: unbounded-set discovery). The candidate fix: a relay-spec `OnValueCross { account, offset, threshold, direction }` wake kind — turners index these per watched account in a priority queue, so evaluation is O(1) per oracle tick and nothing simulates until a threshold actually crosses (the off-chain priority queue Noah wants, driven by on-chain-declared thresholds) — plus a per-market trigger-conditions account whose slots velocity maintains at place/cancel/trigger. Until then, `trigger_clob_order` is cranked by bespoke keepers with their own price queues.

  **Detection is the PropAMM-reprice problem, shared with the book publisher.** A PropAMM's quote is a function of its whole registered `quote_accounts` list — the registry already names the reprice surface — so no single `OnAccountChange` watch captures "this source may have repriced"; relay-spec v0 conditions watch exactly one `(account, offset, len)`. Plan: CLOB×CLOB gets a precise `OnAccountChange` wake over the book's `best_bid`/`best_ask`; the general case gets an `EverySlots` condition whose resolver runs the quote view (`quote_router`) in simulation and stages a match if any pair crosses — hints may fire early, never late, and resolvers are free. The low-latency path is the book publisher: it already subscribes (relay-chain-source) to every registered quote account and re-simulates books on any change, so it detects crosses the moment they land and can submit the executor directly, with the poll condition as the liveness backstop. A relay-spec multi-account watch is a possible later extension; not needed to ship.

- **CLOB cranks via relay, not a bespoke keeper (decided 2026-07-29)** — relay's `demo-book` already models this market's three conditions (its own doc calls the soft-cap one "the CLOB soft-cap pattern"), and the crank ixs built 2026-07-28 are already shaped like relay executors: permissionless, fail-closed, keeper paid from the maker — which is what `min_payment` + `assert_paid_v0` assert. So the keeper work drops out in favour of condition blocks.

  **The condition block lives on a velocity account, not the CLOB's**, and both legs are velocity instructions: removal has to adjust the maker's `User` (open-order aggregates, and the reward debit), which only velocity can do, and the resolver has to stage *velocity's* account list — the maker `User`, the perp market, the filler — not the CLOB's. `target_program` = velocity, so an operator scoping a turner to velocity picks these up.
  - **Evict** (`WakeKind::OnAccountChange`): `wake_account` is the CLOB market with `wake_offset`/`wake_len` covering `bid_count`/`ask_count`. `ConditionV0` names its wake account explicitly, so a velocity-hosted condition watching foreign CLOB bytes is native to the spec — no mirroring.
  - **Expire** (`WakeKind::AtTimestamp`): needs a `wake_ts`, and velocity mediates every placement (`place_clob_order`), so it maintains the min-over-inserts hint in its own condition block as it places. Exact, and no CLOB-side change.
  - The resolver reads the CLOB account to decide whether work exists and which order (`OrderRef`) — solving the "which order expired" discovery that would otherwise be hand-rolled off-chain, since account resolution is program code and can't drift.
  - New per-market PDA to host the blocks: `QuoterV0` has only 8 bytes of padding and a `ConditionV0` is 280, so the conditions need their own account (also bounded by `MAX_RESOLVER_ACCOUNTS`).
  - **Keeper incentive: protocol-owned `User` takes the velocity-side reward, reservoir pays gas (decided 2026-07-29).** relay's `assert_paid_v0` measures the keeper's *lamport* balance, so a crank whose only incentive is quote credited to a velocity `User` cannot express a fee and turners get no signal to prioritize or decline it. `min_payment: 0` would technically pass the guard and was rejected for exactly that reason. The loop closes in three steps: the maker pays the flat removal reward as it does today, but into a **protocol-owned `User`** rather than the keeper's; the per-market conditions account holds a lamport **reservoir** and pays the keeper `keeper_payment_lamports` per crank (rent-exempt floor, failing with `InsufficientCrankReservoir` rather than underpaying, since an underpaid crank fails inside relay *after* doing the work); and a **hot role** withdraws the accumulated quote from the protocol `User` and converts it to SOL to top the reservoirs off. Makers fund gas that way — without the top-off leg the protocol subsidizes crank gas indefinitely.

    The bigger win is the account list. `KEEPER_PLACEHOLDER` substitutes exactly one address, but the executor as built takes the keeper's `User` **and** `UserStats` — PDAs derived from its authority, which a turner cannot derive and which would force every relay keeper to hold an initialized velocity `User` just to crank. Routing the reward to a protocol `User` at a fixed address removes every keeper-derived account from the executor: the staged `ResolvedCrankV0` becomes static except for the single lamport recipient, and the `can_sign_for_user(&filler, &authority)` check drops out. Keepers need only a wallet.

    **Generalizes past the CLOB.** Any crank whose incentive originates inside velocity has this shape — liquidations being the obvious next one — so the protocol-`User` + hot-role-to-gas path is worth building as a reusable pair rather than CLOB-specific plumbing.

    **Settled 2026-07-29:** *one* protocol `User` serves every crank (the reward is fungible; per-domain accounting isn't worth an account per domain). Crank endpoints stay **dual-mode**: the same instruction is callable the way it is today — keeper passes its own `User`/`UserStats`, signs for it, takes the quote reward, no lamports move — or in program-keeper mode, where the reward accrues to the protocol `User` and the caller is paid reservoir lamports instead. The mode follows from *which* `filler` is passed, so there is no flag: `filler == protocol_user` selects the lamport payout, anything else takes the existing signed path. That means relaxing today's `can_sign_for_user(&filler, &authority)` to "signs for the filler **or** the filler is the protocol `User`" — nobody can sign for the protocol `User`, since its authority is the protocol signer. No gate is needed on the lamport payout beyond the work itself: a caller only reaches it by actually removing an expired or evictable order, which is precisely the bounty we want to pay. Keeping both modes matters because it decouples shipping the cranks from standing up relay — the existing litesvm tests keep exercising the signed path unchanged.

    **Quote → SOL stays off-chain.** A hot role withdraws quote from the protocol `User` and swaps it on Jupiter out of band; no on-chain conversion, no swap CPI in the crank path. The only new instruction is a hot-role withdraw. Deliberately dumb: an on-chain auto-conversion would drag the swap path, slippage policy and an oracle into a plumbing job that a human doing a periodic swap solves for free.
